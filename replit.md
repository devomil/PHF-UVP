# AI Video Production Studio

## Overview
The AI Video Production Studio is a full-stack platform designed to streamline video creation using multiple AI video providers. Its core purpose is to offer an intelligent system for provider selection with content-aware classification, comprehensive brand asset management, quality evaluation, and advanced sound design capabilities. The platform leverages Remotion for flexible video composition, targeting a broad market with ambitions to be a leading tool for professional and efficient AI-driven video production.

## User Preferences
- Focus on Video Production Platform only (no HR features)
- Dark theme with purple/indigo accent colors
- Modern, professional, cutting-edge UI (Canva-inspired)
- Glassmorphism card surfaces, gradient thumbnails, visual project cards

## Contributor Conventions
- **No native browser pop-ups in `client/src`**: never use `window.confirm`, `window.alert`, `window.prompt`, or their bare unqualified equivalents (`confirm(...)`, `alert(...)`, `prompt(...)`). They cannot be themed against the dark UI, are inaccessible, and cannot be reliably tested. Use the themed `AlertDialog` from `@/components/ui/alert-dialog` for blocking confirmations (model the dialog after `client/src/pages/asset-library.tsx`, `client/src/pages/project-detail.tsx`, `client/src/pages/api-testing.tsx`, `client/src/components/settings/CanvaConnect.tsx`, `client/src/components/video/universal-video-producer.tsx`, or the saved-set delete dialog in `client/src/components/video/brand-reference-panel.tsx`), and use `useToast` from `@/hooks/use-toast` for non-blocking alerts. The check `npm run lint:dialogs` (`scripts/check-no-native-dialogs.sh`) greps `client/src` for any new occurrences (both `window.*` qualified and bare-global calls) and exits non-zero. The very rare intentional exception can be opted in with a `// allow-native-dialog` comment on the same line.
- **`lint:dialogs` runs automatically on every change**:
  - **CI (GitHub Actions)**: `.github/workflows/lint.yml` runs `npm run lint:dialogs` on every push and pull request (Node 20 on `ubuntu-latest`, with a defensive ripgrep install). A failing check blocks the merge.
  - **Local pre-commit hook (Husky)**: the `prepare` npm script invokes `husky`, which points `git config core.hooksPath` at `.husky/_`. The hook at `.husky/pre-commit` runs `npm run lint:dialogs` and aborts the commit if the script exits non-zero. After cloning, contributors only need to run `npm install` once for the hook to be installed; set `HUSKY=0` to skip installation in environments where git hooks aren't wanted.

## System Architecture
-   **Tech Stack**: React 18, Vite, TypeScript, Tailwind CSS v4, shadcn/ui, wouter, @tanstack/react-query for frontend; Express.js, TypeScript, Passport.js, bcrypt for backend; PostgreSQL (Neon) with Drizzle ORM for database; Remotion for video composition.
-   **UI/UX**: Canva-inspired persistent sidebar navigation, glassmorphism card surfaces, animated gradient landing page, split-panel authentication, and visual project cards with gradient thumbnails. Modern dark theme with dynamic light/dark mode toggling.
-   **Brand Management**: Integrated brand settings (name, tagline, website, colors, logo_url, guidelines, industry, contentNiche, targetAudience, trendAnalysisEnabled) for dynamic injection into project creation, script parsing, and video prompt optimization. Supports drag-and-drop logo upload and brand media library.
-   **Trending Hook Intelligence**: AI-powered trend analysis combining Google Trends rising queries, YouTube trending videos (industry-mapped categories), and Claude web search to generate viral hook suggestions, trending keywords, and content format recommendations. Results cached in `trend_cache` table (24h TTL, keyed by industry+niche+audience). API at `/api/trend-intelligence/hooks` (GET) and `/api/trend-intelligence/refresh` (POST, 1h cooldown). Requires industry set in Brand Settings with trendAnalysisEnabled toggle. Dedicated `/trends` dashboard page with hook library cards (copy + use buttons), keyword momentum tags, content format cards, trend insight section, refresh with cooldown, locked/blurred state when disabled, and "Create Video Using These Trends" CTA. Hook chips integrated into AI-Generated Script project creation flow — 3 clickable suggestions above the brief field with tooltip showing psychological driver. Hooks can be pre-populated via `?hook=` query parameter from the trends dashboard.
-   **AI Video Generation**: Universal image-first (I2V) pipeline — ALL 9 art presets now use `generationStrategy: 'i2v'` (cinematic-realism changed from 'auto', neon-futuristic from 't2v'). Every scene first generates a Flux Pro intermediate image, then animates it via I2V. All 9 presets have `sceneTypeProviderMap` for scene-type-aware provider routing (previously only 3d-illustration had one). Stage 4 dual-prompt system: `imagePrompt` (still-image description for Flux, no motion words, 50-80 words) + `motionPrompt` (motion-only description for I2V, 15-30 words) + `providerHint` (scene-type-based provider from sceneTypeProviderMap). Worker uses `imagePrompt` for Flux generation and `motionPrompt` as I2V animation prompt when I2V source image exists. `textImageEnabled` auto-detected per scene by Stage 4 LLM for text-heavy narrations (stats, lists, steps). Both `ai-video-service.ts` and `intelligent-provider-selector.ts` honor these mappings. Stylized preset style consistency: cfg_scale is overridden from 0.10 to 0.30 for stylized presets in CHARACTER REFERENCE I2V mode (preserves art style adherence), and environment style reinforcement suffix is appended to all stylized preset prompts (both I2V and T2V) to prevent photorealistic drift in backgrounds. Scene and micro-scene regeneration endpoints enforce image-first I2V for stylized presets with `generationStrategy: 'i2v'` — when no source image exists, a Flux Pro intermediate image is generated with retry logic (2 attempts). Stylized presets with character reference images now use the character reference as I2V source (anchoring both style and character consistency) instead of skipping it. `runway-gen4-aleph` model mapping fixed to `gen4.5` (was invalid `gen4_aleph`). TIER_PROVIDER_VERSIONS runway premium mapped to `runway-4.5`. Two-tier cfg_scale override for stylized I2V: `STYLIZED_CHARACTER_CFG = 0.85` (face/wardrobe lock) and `STYLIZED_ENVIRONMENT_CFG = 0.75` (style anchor, more motion freedom) — constants in `shared/config/visual-art-presets.ts`, applied in `piapi-video-service.ts`. T2V does not support cfg_scale; style adherence for T2V relies on prompt engineering (style reinforcement suffix, negative prompts).
-   **Character Reference Pipeline**: When "3D Illustration" art style is selected, a "Character Profiles" panel appears in the scene editor. Users can define up to 5 characters (name, role, physical description, wardrobe, personality notes), generate Disney/Pixar-style reference images via Flux Dev, and lock them. Supports optional reference photo upload — when a photo of a real person is provided, the system uses I2I (image-to-image) generation with the Disney/Pixar prompt to produce a character that resembles the person (strength: 0.65). Locked characters' reference images are automatically injected as I2V inputs when their name appears in scene narration/visual direction (word-boundary regex matching). Supports multi-image I2V for providers with `multiImageSupport` (e.g., Seedance 2.0). Includes drag-to-reorder for character priority, clickable name chips for inserting exact names into narration, and an account-level Character Library (`character_library` table) for reusing characters across projects. Character Profiles panel also appears on the project creation page (`/projects/new`) in standalone mode (no projectId needed). A "Character I2V" video generation method forces I2V with character references for all matching scenes. Characters can also be created in the Asset Library via a dedicated "Character" mode in the Create Asset dialog, and saved characters appear in a "Characters" tab in the Asset Library page.
-   **Micro-Scenes**: Claude automatically splits scene narrations into micro-scenes, each with its own visual direction and AI-generated video clip. Remotion stitches these with crossfade transitions. Supports per-micro-scene original audio mixing with volume control and background music auto-ducking. Micro-scenes are always visible in the scene editor (even for single micro-scene scenes). Supports concurrent regeneration of multiple micro-scenes simultaneously via `regeneratingMicroScenes: Set<number>` state tracking. "Generate All Micro Scenes" uses a batch endpoint (`POST /:projectId/scenes/:sceneId/regenerate-all-micro-scene-videos`) that reads project state once, takes an immutable art preset snapshot, generates all stylized images serially, saves all imageUrls atomically via `batchUpdateMicroSceneImageUrls`, and creates all video jobs — eliminating the concurrent save race condition. Individual micro-scene regeneration uses `updateMicroSceneImageUrl` for atomic field-level saves. Both functions defined in `video-project-db.ts`. Progress shows per-micro-scene status with counters. Race condition fix: video worker writes scene data BEFORE marking job as succeeded, and frontend reconciliation keeps spinners alive for up to 3 poll cycles after jobs complete to ensure query refetch brings in fresh data before clearing UI state. **Atomic scene video updates**: `updateSceneMedia` in `video-generation-worker.ts` uses PostgreSQL `jsonb_set()` for atomic per-scene video URL writes instead of Read-Modify-Write pattern, preventing concurrent video generation jobs from overwriting each other's scene data. **Atomic per-scene patches** (Task #108): `patchSceneAtomic(projectId, sceneId, patch)` in `server/services/video-project-db.ts` is the centralized lost-update-safe primitive — it runs `jsonb_agg` over the row's CURRENT `scenes` value in a single UPDATE so two concurrent writers (e.g. the NB2 storyboard batch and a user editing a sibling scene) can't clobber each other. Used by the storyboard service (`scene-image.service.ts`) and the legacy Flux thumbnail endpoint in `universal-video-routes.ts`. The micro-scene helpers in the same file follow the same pattern with chained `jsonb_set` calls.

-   **Intelligent Script Pipeline**: Four-stage AI pipeline (`server/services/script-pipeline-service.ts`) for all project types. Stage 1 (Creative Strategy): develops narrative framework, core message, emotion, hooks using brand settings + trend data + product context. Stage 2 (Narrative Architecture): builds scene-by-scene structure with duration budgets and platform-specific rules. Stage 3 (Scene Writing): writes narration and visual directions with art preset rules (stylized vs realistic). Stage 4 (Visual Direction Enhancement): transforms generic visual directions into production-grade AI video prompts using Suzzie's 7-layer cinematic framework (subject anchor, environment description, lighting design with named setups, color palette, camera specs, mood/atmosphere, technical markers). Includes visual metaphor guidance for abstract/emotional concepts, narrative flow context (previous scene narration/visual direction injected per scene for continuity), scene-type-specific frameworks (hook, testimonial, product, lifestyle, educational, chapter-title, etc.), micro-scene breakdowns with `pipelineStage: 4` marker, per-scene `cinematicNotes` and `negativePrompt`, and dynamic art preset/provider hint integration. Strict "NO text in AI video" enforcement — all text/logos/typography banned from visual directions. `enhanceChapterTitleVisualDirections()` generates cinematic visual metaphors for chapter-title scenes via LLM, wired after chapter-title scene creation in `universal-video-routes.ts`. Stage 4 micro-scenes skip independent generation in `universal-video-service.ts`. Per-scene `negativePrompt` flows through all `generateVideo` call sites (single-scene, deferred parallel, micro-scene, I2V fallback, T2V fallback, regenerate). `cinematicNotes` displayed as expandable detail in scene editor UI. Stage 4 fails gracefully — Stage 3 output preserved on error. Strategy and narrative stored as JSONB columns (`script_strategy`, `script_narrative`) on `universal_video_projects`. Collapsible "Creative Strategy" panel on project detail page shows framework, core message, emotion, tone, audience insight, production notes, and generated hooks. **Chapter-based (Long Story) projects now also go through Stage 4** via `enhanceChapterScenesWithStage4()` — content scenes get full cinematic enhancement while chapter-title scenes preserve their pre-generated cinematic metaphors. Pipeline completely bypasses `health-script-context.ts` hardcoded Pine Hill Farm persona.
-   **Text-Aware Image-to-Video Pipeline**: Two-step generation for text-heavy scenes (chapter-title, infographic, scenes with text overlays): GPT-Image-1 generates a text-accurate image first, then I2V animates it with subtle cinematic motion. `isTextHeavyScene()` utility in `image-generation-service.ts` detects text-heavy scenes by type, `textImageEnabled` flag, visual direction keywords (including `imagePrompt` field), or title-style text overlays. `generateWithOpenAI()` method on `ImageGenerationService` calls GPT-Image-1 API, uploads base64 responses to S3. **Early routing in `generateContentImage`**: Text-heavy scenes are detected at image generation time (not deferred to the video worker), so GPT-Image-1 is used instead of Flux for the initial content image. Micro-scene temp scenes propagate `imagePrompt` for accurate text-heavy detection. Source classification treats `gpt-image-1` outputs as AI-generated (not stock). Video worker (`video-generation-worker.ts`) also pre-generates text image before video generation when scene is text-heavy and has no source image, saves `textImageUrl` to scene data atomically via `jsonb_set()`, then uses it as I2V source with a subtle animation prompt. Chapter-title scenes auto-flagged with `textImageEnabled: true`. **Narration-based auto-detection**: `autoFlagTextHeavyScenes()` in `script-pipeline-service.ts` scans narration for text-heavy keywords (FDA-approved, clinically proven, statistics, percentages, certifications, patent references, study/research citations) and auto-flags matching scenes with `textImageEnabled: true` at script generation time. -   **Post-Production & Rendering**: Render configuration panel for voiceover, background music volume, sound design, film treatments, captions, and transitions (all toggleable on/off). Uses Remotion Lambda for rendering with live progress polling and chunked rendering for longer videos. **Studio Polish passthrough optimization**: When a Studio Polish project has transitions OFF, film treatment OFF, and scenes have no captions or text overlays, video chunks skip Remotion Lambda entirely and use the original uploaded video directly (download + optional FFmpeg trim for frame-range sub-chunks + re-encode to H.264/AAC for concat compatibility). Only intro/outro cards go through Lambda. This reduces render time from ~80 min to minutes for clean passthrough scenarios. Two-stage rendering pipeline: FFmpeg pre-compositor (`server/services/ffmpeg-assembly-service.ts`) concatenates micro-scene clips into a single assembled video per scene during S3 asset caching (Stage 1), then Remotion plays the assembled clip as a single `<OffthreadVideo>` instead of managing per-micro-scene sequences (Stage 2). If assembly fails, the `assemblyManifest.assemblyFailed` flag triggers graceful fallback to the original per-micro-scene rendering. Assembly manifest (`AssemblyManifest` type in `shared/video-types.ts`) includes per-clip timing data, word-level sync markers (`AssemblyWordMarker[]`) mapped from voiceover word timing with micro-scene index tagging, and staleness detection covering both video URL changes and voiceover word count changes. Remotion `SyncedCaptions` prefers manifest word markers when assembly is valid, preserving caption-to-audio sync. Manual testing via `POST /api/universal-video/test-assembly/:projectId/:sceneIndex` (admin-only). **Black-frame trimming**: FFmpeg `blackdetect` filter in `detectBlackIntro()` identifies dark intro frames (up to 1s, brightness threshold 0.02) on each clip before normalization; detected clips are trimmed via `-ss` during `normalizeClip()`. Post-normalization duration re-probing ensures manifest timing accuracy. Remotion fallback path applies `startFrom={AI_VIDEO_TRIM_FRAMES}` (9 frames / 0.3s at 30fps) to individual micro-scene `SafeVideo` and `MicroSceneAudioVideo` components when assembly is not available.

Sidebar nav items: "Social Hub" and "Calendar". Safety: profileKey logged to server error log as recovery mechanism if DB write fails after Ayrshare creation. Requires `AYRSHARE_API_KEY` env var.

## Deployment
-   **Target**: Autoscale (Replit Deployments)
-   **Build**: `vite build && esbuild server/index.ts --bundle --platform=node --format=esm --packages=external --outdir=dist/server`
-   **Run**: `NODE_ENV=production node dist/server/index.js`
-   **Health Check**: `GET /api/health` returns `{"status":"ok","timestamp":"..."}`
-   **Session Security**: `trust proxy` enabled in production, secure cookies enforced, `SESSION_SECRET` env var required (fails fast if missing in production)
-   **Auth**: All project endpoints require authentication + ownership verification (IDOR protection)
-   **Static Serving**: Production serves pre-built Vite output from `dist/public/`

Provider routing: `server/utils/image-generation-policy.ts` selects providers based on visual style and scene content type — Recraft preferred for text-heavy/product scenes, NB2 preferred for photorealistic/lifestyle scenes.
